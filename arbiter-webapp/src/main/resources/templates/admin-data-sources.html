OpenSearch

Add OpenSearch data source

Register an OpenSearch instance that documents can be pulled from. Specify the endpoint and a query (typically the JSON body of an _search request, including the index path) that returns the documents to import. Names must be unique.

Field name within each hit's _source that holds the text to import.

Optional. Field within each hit's _source whose value is used as the imported document's filename. If blank, the OpenSearch _id is used.

Leave Username and Password blank for unauthenticated OpenSearch endpoints. Passwords are encrypted at rest with the application's symmetric key.

S3-Compatible

Add S3-compatible data source

Works with any S3-compatible storage — Amazon S3, MinIO, Cloudflare R2, Backblaze B2, and similar. Specify the bucket, the key (prefix) under which to look, and a filename glob filter (for example *.txt or **/*.pdf). Names must be unique.

Leave the Endpoint URL blank to use Amazon S3 with the AWS default endpoint; set it to point at MinIO (e.g. http://minio:9000), Cloudflare R2, Backblaze B2, or any other S3-compatible storage. Leave Access key and Secret key blank to use the application's ambient AWS credentials (environment / instance profile). When provided, both keys are encrypted at rest with the application's symmetric key.

Relational Database

Add relational database data source

Register a JDBC-accessible database that documents can be pulled from. Specify the JDBC URL and a SQL query whose first column returns the document text. Names must be unique. Username and password are encrypted at rest with the application's symmetric key.

The first column of each returned row is treated as the document text.

Leave Username and Password blank to use credentials embedded in the JDBC URL or the driver's ambient authentication.
